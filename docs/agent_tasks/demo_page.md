## How a tile plays a replay

Each tile is an iframe (same origin) loading the vendored game's entry page with `games/_shared/pj_shim.js` and
`games/<id>/pj_hook.js` injected first. The driver injects them with Playwright's add_init_script; on the demo page do
the equivalent by having the build script write, for each game, a `demo/games/<id>/<entry>` copy whose `<head>`
starts with `<script src="../_shared/pj_shim.js"></script><script src="pj_hook.js"></script>` (before any game
script; verify the hook still registers, some hooks listen on document DOMContentLoaded and must be registered
before the game's own listeners). Then the page calls, inside the iframe, `pj.start(seed)` and `pj.step(a)` per
recorded step with a timer at the chosen speed (1x = the game's real step time: frames_per_step x 16.67 ms; turn-based
games use 150 ms per move), draws the probability bars from the recorded `p`, highlights the taken action, shows the
Jev confidence `(p_max - 1/K)/(1 - 1/K)`, the step counter and the score. Verify per game that the replayed score
equals `final_score` in the file at the end (print a mismatch warning in the console and a small red mark on the tile).
Only vendored assets the entry page needs get copied (walk the entry page's script/link/img references plus the
folders the hooks need; the sokoban levels module, the mario sprites, sounds can be left out if the game tolerates
it, otherwise copy them).

Style rules: plain sentences, no oversized headline with a grey caption under it, no uppercase eyebrow
labels, no em-dashes anywhere, no decorative gradients. Palette: JEV blue #2F80ED for the chosen action's bar, coral

mode and #111 in dark mode via prefers-color-scheme with a manual toggle. System font stack. The game canvases are the
visual; keep the chrome quiet and the bars readable at tile width. Everything works at 400 px width. No external
resources (no CDN, no web fonts): the page must run from file:// and from GitHub Pages alike.
